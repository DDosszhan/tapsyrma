# Tapsyrma

Платформа для ретейков формативных и суммативных работ. Работают создание экзамена, генерация вопросов через OpenAI, персональные коды, сдача и проверка ответов. Общая схема — в [архитектуре](ARCHITECTURE.md).

## Локальный запуск

Нужен Docker с работающим Linux Engine. Локальный `.env` уже создан; если его нет, скопируйте `.env.example` в `.env` и замените `DJANGO_SECRET_KEY` и `POSTGRES_PASSWORD` длинными случайными значениями.

```sh
docker compose up --build -d
docker compose exec web python manage.py createsuperuser
```

Откройте `http://localhost/admin/` и войдите созданным администратором. `http://localhost/` — вход ученика по коду, `http://localhost/healthz/` проверяет также соединение с PostgreSQL. Для генерации и проверки открытых ответов добавьте свой `OPENAI_API_KEY` в локальный `.env`. `OPENAI_MODEL` по умолчанию — `gpt-4o-mini`; можно поменять на совместимую со Structured Outputs модель. Ключ никогда не передается браузеру.

## Создание экзамена

В разделе «Экзамены» укажите название, предмет, 9-й или 10-й класс, общее количество вопросов и баллов. В строках «Типы вопросов» добавьте MCQ с одним правильным ответом и/или открытые вопросы; удалите строку, чтобы исключить тип. Количество вопросов и баллы по строкам должны точно совпадать с итогами экзамена.

Силабус можно вставить текстом или загрузить TXT, PDF либо DOCX до 10 МБ. Из файла извлекается текст, а оригинал хранится отдельно и доступен только администратору. После сохранения проверьте текст: PDF-сканы без текстового слоя требуют ручного OCR или вставки текста. Баллы за каждый вопрос должны быть целыми.

В списке экзаменов нажмите «Сгенерировать раунд». Каждый раунд добавляет по одному альтернативному вопросу на каждое место экзамена. Проверьте в карточке экзамена формулировки, ключи, критерии и объяснения. Неудачный черновик удалите в разделе «Сгенерированные вопросы» и запустите новый раунд. Только после проверки включите «Опубликован». Система фиксирует эти данные: после публикации генерация отключена. Разные попытки получают разные сочетания вопросов при неизменном количестве, типах и баллах. Число сочетаний равно произведению количества альтернатив для каждого места; при исчерпании новых вариантов старт сдачи блокируется. Для одного вопроса и 100 учеников нужны 100 альтернатив, для двух — по 10 альтернатив на каждое место. Планируйте генерацию до публикации.

В «Ученики» добавьте имя, класс и постоянный ID. В «Коды на сдачу» выберите опубликованный экзамен, ученика и срок начала. Случайный 8-символьный код появится **один раз** после сохранения; выдайте его ученику лично. При потере кода используйте действие «Перевыпустить коды»: старый перестанет работать, уже начатая попытка сохранится. Ученик вводит код, начинает экзамен, ответы сохраняются автоматически и при отправке. Повторный вход до отправки возвращает ту же работу. После сдачи фоновый `worker` выставляет баллы: MCQ по сохраненному ключу, открытые ответы через ИИ по заранее сохраненным критериям. В «Сдачи» видны все результаты, а ошибочную проверку можно отправить повторно. Ученик видит итог, баллы за каждый критерий и объяснения только после проверки.

Чтобы учитель мог выдавать коды и видеть работы, администратор создает ему учетную запись Django с `is_staff` и разрешениями на учеников, приглашения и просмотр сдач. Создание экзаменов и генерация доступны только суперпользователю.

Для 9 класса генерация ориентируется на Cambridge IGCSE, для 10 класса — на Cambridge International AS Level: командные слова, уместная глубина применения знаний и распределение целых баллов по шагам. Это оригинальные задания Tapsyrma, не официальные материалы Cambridge. ИИ может ошибаться в вопросах и оценивании: администратор проверяет банк до публикации, учитель решает, какую оценку выставить в EduPage.

## Проверка кода

```sh
docker compose exec web python manage.py test exams --settings=tapsyrma.test_settings
```

## Перед запуском на VPS

В `.env` установите `DJANGO_DEBUG=0`, `SITE_ADDRESS=ваш-домен`, `DJANGO_ALLOWED_HOSTS=ваш-домен` и `DJANGO_CSRF_TRUSTED_ORIGINS=https://ваш-домен`. Направьте DNS на VPS и откройте порты 80/443; Caddy получит HTTPS-сертификат. Не публикуйте порт PostgreSQL. Настройте внешние резервные копии базы до работы с реальными результатами.

`.env` и приватные ключи игнорируются Git и Docker. В репозиторий отправляйте только `.env.example` с фиктивными значениями. Перед `git push` проверяйте `git diff --cached --name-only` и `git ls-files`.
