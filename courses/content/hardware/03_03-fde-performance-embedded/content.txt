## Fetch–Decode–Execute, CPU Performance and Embedded Systems

### Learning goals

By the end of this lesson, you should be able to trace the fetch–decode–execute cycle, explain how clock speed, cache and cores affect performance, and recognise an embedded system.

### Why this matters

A computer repeats a cycle of fetching, decoding and executing instructions. Understanding the cycle helps explain why registers matter and why CPUs with different cores, caches and clocks can perform differently.

### Step 1: Fetch

Copy the address in PC to MAR; transfer the address on the address bus; issue a read signal; bring the instruction back over the data bus into MDR; copy it into CIR. PC is updated to the next instruction address during the cycle.

### Step 2: Decode

The CU interprets the instruction in CIR and determines the operation and resources needed.

[diagram:fde-cycle]

### Step 3: Execute

The CPU carries out the instruction. The ALU performs arithmetic/logic if required, with intermediate results often stored in ACC.

### Step 4: Performance factors

Clock speed is the number of clock cycles per second; a higher speed can allow more work per unit time, all else equal. Cache is fast memory for frequently needed data/instructions. Multiple cores can work on separate instruction streams, if software allows.

### Step 5: Instruction set and embedded systems

An instruction set is the collection of machine-code instructions a CPU understands. An embedded system is a computer designed to perform dedicated functions inside another device, such as a washing machine.

[diagram:performance]

### Worked example 1: A simple addition instruction

A stored instruction requests adding 2 to a value. The instruction is fetched into CIR, decoded by CU, and executed using the ALU. The result may be stored in ACC.

### Worked example 2: Two phones with the same clock speed

Phone A has a larger useful cache than Phone B. Even with the same clock speed, Phone A may avoid some slower main-memory accesses. Performance cannot be predicted from clock speed alone.

### Common mistakes

Tip: Some instructions move data or change program flow without using the ALU for arithmetic.

Tip: Extra CPU cores help most when work can run in parallel; they do not guarantee twice the speed.

Tip: An embedded system is defined by its dedicated function, not simply by its size.

### Quick recap

Fetch uses PC/MAR/MDR/CIR and buses; CU decodes; execution carries out the instruction. Clock, cache and cores influence CPU performance. Embedded systems do dedicated jobs.
